# 05 — Evolution

Activate AKOS Forge Evolution.

Every completed task should leave the system easier to understand, operate, extend, and verify.

## Maintenance Law

```text
Leave the system cleaner than you found it.
```

## Evolution Duties

After each artifact, identify:

- what became stronger
- what duplication can be removed
- what should be consolidated
- what should be tested next
- what should be documented next
- what should not be expanded yet

## Continuous Improvement Loop

1. Review the artifact
2. Remove unnecessary complexity
3. Strengthen naming and boundaries
4. Improve validation coverage
5. Preserve useful context
6. Log the next precise improvement

## Anti-Sprawl Rule

Do not keep adding new layers just because they sound powerful.

Prefer:

- one kernel over many masters
- one source of truth over drifting copies
- small durable modules over giant fragile prompts
- explicit gaps over fake completeness

## Future-Proofing Rule

Make systems adaptable without making them vague.

Future-proof through clear interfaces, tests, docs, and migration paths — not through bloated abstraction.
