# Web Design Pro Stone

**ID:** `stone-web-design-pro`  
**Version:** `0.2.0-candidate`  
**Status:** `CANDIDATE_EXTENSION`  
**Prior verified baseline:** `0.1.0` repository-local `TEST`  
**Evidence target:** repository-local `TEST` plus browser, accessibility, interaction, and production reconstruction receipts

Web Design Pro converts one canonical fact and evidence graph into an adaptive website that can teach, persuade, orient, verify, and route work without creating separate truths for separate audiences.

It is not limited to a document-shaped page. It may express the same source graph through hierarchy, timelines, dependency graphs, constellations, mind maps, state machines, comparison matrices, animated explanations, interactive proof trails, and role-specific pathways. Every projection remains subordinate to canonical facts, evidence state, privacy policy, accessibility, and PSYSOC-X dignity boundaries.

## Core Contract

```text
canonical evidence graph
+ PSYSOC-X audience/decision profile
+ Monolith repository/capability graph
+ approved artifact and deployment manifests
        ↓
multidimensional experience architecture
        ↓
semantic routes + progressive disclosure + graph projections
        ↓
responsive visual system + bounded interaction + motion grammar
        ↓
accessibility + performance + integrity + privacy verification
        ↓
preview receipt → production reconstruction receipt → promotion gate
```

## The Website Is an Executable Master Class

The website must let a reviewer move through the same truth at different depths:

1. **Signal layer** — role, value, strongest proof, and next action.
2. **System layer** — flagships, capabilities, company bottlenecks, and combined value.
3. **Graph layer** — repositories, dependencies, donors, evidence, and provenance.
4. **Proof layer** — commands, receipts, limitations, current state, and exact source.
5. **Learning layer** — explainers, architecture walkthroughs, domain libraries, and decision models.
6. **Machine layer** — structured data, schemas, stable identifiers, and queryable projections.

No reader is forced through every layer, and no shallow layer is permitted to overstate what the deeper layer proves.

## Supported Dimensions

- **Hierarchy:** domain → company → bottleneck → capability → system → repository → proof.
- **Graph:** dependencies, capability donors, shared primitives, provenance, and evidence edges.
- **Time:** evolution, releases, decisions, regressions, recoveries, and current freshness.
- **State:** discovered, classified, admitted, verified, promoted, blocked, quarantined.
- **Audience:** recruiter, engineer, executive, operator, investigator, collaborator, machine.
- **Comparison:** alternative architectures, tradeoffs, bottlenecks, and solution fit.
- **Spatial:** constellations, zoomable maps, clusters, and focus-plus-context navigation.
- **Narrative:** guided tours that preserve source links and allow immediate branch-off.

## Activation Sequence

Before material web work:

1. Resolve the latest canonical website source and production deployment.
2. Activate PSYSOC-X for the explicit audience, decision, stakes, and desired action.
3. Activate Monolith for repository-scale discovery, ownership, and dependency context.
4. Discover current tools, connectors, standards, and browser capabilities; do not freeze moving inventories into source arrays.
5. Build or refresh the experience graph from current facts, evidence, and policy overlays.
6. Select the minimum interaction and visualization set that materially improves comprehension.
7. Implement semantic fallback first; enhancement must never become the only path to meaning.
8. Verify responsive, keyboard, screen-reader, reduced-motion, contrast, zoom, performance, links, privacy, and exact production reconstruction.

## Dynamic-Target Rule

Hard-code only stable schemas, invariants, authority rules, token contracts, and validation gates.

Discover and snapshot mutable entities such as repositories, companies, evidence states, routes, connector capabilities, role families, and production revisions. Every generated projection must expose its source revision, observation time, scope, and freshness.

## Interaction and Motion Doctrine

- Motion explains state, causality, hierarchy, or transition; it is never ornamental obligation.
- Every animation has a reduced-motion and non-animated equivalent.
- Every graph has a textual/table representation and deterministic focus order.
- Every interactive filter preserves a shareable, reconstructable state.
- Progressive disclosure reduces cognitive load but may not bury limitations.
- Client code must be bounded by an explicit benefit, budget, failure mode, and fallback.
- The user controls depth, movement, comparison, and exploration.

## Non-Claims

A design specification is not an implemented website. A template is not a deployment. A visualization is not evidence. A graph edge is not proof of runtime behavior. A limited accessibility audit is not certification. A preview is not production. Animation does not establish sophistication. Visual prominence cannot promote evidence.
